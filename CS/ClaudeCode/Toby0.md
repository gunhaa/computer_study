# Claude Code 기본

- Claude Code는 챗봇의 한 형태이다
- Agentic Loop(컨텍스트 수집 → AI 지시 → 도구 실행 → 결과 반환 → 반복)를 통해 실행되며, Claude LLM 모델의 harness 형태이다
  - 우리는 기본적으로 harness가 적용된 모델에 커스텀한 workflow, 반복 가능한 Skills 등을 부여해 작업하는 것이다
  - agentic loop의 각 단계에 hook을 이용해 커스텀한 작업이 가능하다
- context에 어떤 것이 담기는 지를 이해 해야한다
  - 대화 히스토리가 길어지면 AI 효율이 떨어진다. 현재 작업과 무관한 과거 대화가 쌓이면 AI가 혼란스러워한다(context가 20%가 넘어가면 `/clear`로 제거하는 것이 효율적이다)
  - 도구 목록도 MCP를 많이 설치하면 비대해진다. 스킬은 상대적으로 가볍다.
```plaintext
시스템 프롬프트 (Claude Code 팀이 세팅한 고정 규칙)
  +
대화 히스토리 (이전 모든 사용자↔AI 메시지 쌍, 세션 내 누적)
  +
도구 목록 (기본 도구 + 플러그인 + MCP + 스킬 + 에이전트)
  +
최신 프롬프트 (방금 입력한 내용)
```

## AI 개발 실력 키우는 법

- 주기적으로 `~/.claude` 폴더 백업 후 제거
  - 워낙 변화가 빨라서, 이를 제대로 적용시키기 위해서는 이전의 메모리와 설정을 초기화 해야한다
- claude code 공식 페이지에는 양질의 정보가 많으며, 제대로 사용하기 위해서는 이를 전부 숙지하고 있어야 한다
- 기본적으로 가장 확률이 높은 이야기를 하는 것이 LLM이기에, 출력 값을 예상하면서 작업을 진행한다
  - e.g. 프로젝트를 만들어 달라고하면 spring initizalizer를 통하지 않는게 기본동작이며, 이를 극복하기 위해 skills를 이용해 워크플로우를 생성해둔다
- AI가 만든 코드를 반드시 리뷰한다
  - AI가 작업하는 동안 놀지 않는다. 병렬 세션 활용, 다른 기능 개발, 또는 Claude Code 학습
- 한번에 다 시키지 않는다
  - `plan.md`, `spec.md`, `tasks.md`, `openapi.yml`을 사용해 더 명확하게 다룬다
- 반드시 검증까지 해야한다
  - 코드를 만들고 끝내면 안 된다. AI에게 검증까지 포함시켜야 한다

## 실전 워크플로우 — 전체 개발 흐름 요약

### Phase 0: 환경 준비

1. `~/.claude` 리셋 (주기적)
2. 공식 플러그인 최소 설치
3. 터미널 세팅, 상태 표시줄 구성

### Phase 1: 프로젝트 생성

1. 빈 폴더 생성
2. Plan 모드로 AI의 기본 판단 확인 → 교정
3. Spring Initializr 경유하여 프로젝트 생성
4. 빌드로 환경 검증
5. IDE에서 의존성·패키지 구조 확인
6. Git 초기화 + 원격 리포지토리 생성

### Phase 2: 기획 문서 작성

1. `prod.md` 생성(Product Requirements Document) → 리뷰 후 보완
2. SDD 변환(Requirements를 제작하기 위해, Phase를 나눈다): Phase를 나누어 가장 단순한 것부터 시작하도록
3. Task 리스트 생성: `tasks.md`에 체크박스 형태로

### Phase 3: 코딩 컨벤션 확립

단일 단위로 전 레이어 한 사이클 → AI의 기본 습관 파악 → 교정 → `CLAUDE.md` 기록.
이 과정에서 AI가 잘하는 것은 `CLAUDE.md`에 넣지 않는다.

### Phase 4: 본격 개발

1. `tasks.md` 기반으로 일괄 개발 ("이 항목들 개발하고 완료되면 체크해줘")
2. 호환 문제는 AI가 웹 검색으로 자체 해결 (한 번 해결하면 반복하지 않음)
3. 프론트엔드까지 포함한 일괄 진행
4. 라이브 앱 데모 → 버그 발견 시 자연어로 설명하면 AI가 원인 분석·수정

### Phase 5: 품질 향상 사이클

```
코드 품질 감사 에이전트 실행 (서브 에이전트, 백그라운드)
  ↓
리포트에서 이슈 추출 → GitHub Issue 또는 로컬 태스크로 등록
  ↓
이슈 하나씩 TDD 팀으로 수정
  · Red: 문제를 재현하는 실패 테스트 작성
  · Green: 수정 코드 작성
  · Refactor: 정리
  ↓
멀티 모델 토론 (선택)
  · Codex에게 리뷰 위임 → Claude에게 "동의하냐? 반박해봐"
  · 합의된 개선 사항만 적용
  ↓
커밋
```
